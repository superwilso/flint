## Part F — F1: what a sync owns (open, owner decision)

The window asks for "the drive the player appears as", and the README says `--to E:\`.
* Scrobbles, likes and palettes treat that path as the **drive root**.
* `likes::Volume::music_dir()` puts music in `<root>/MUSIC`.
* The **sync** treats the same path as the **music root**: it copies to `<root>/<library path>`,
  keeps `flint-manifest.tsv` there, and sweeps every audio file under `<root>` that the plan does
  not place.

Its rules came from `Sony-sync`, whose root was `/contents/MUSIC`. `MANAGED_PLAYLISTS` ("Liked
Songs", which Flint writes into `MUSIC/`) still assumes that root.

Reproduced on a scratch "player" with music in `MUSIC/` and a loose playlist:

```
$ flint sync <lib> --to <player> --gb 1
plan: 1 to copy (0 tagged with SensMe data), 3 to remove, 0 playlists to write
  would remove  <player>/MUSIC/Old - Album/01.flac
  would remove  <player>/MUSIC/Old - Album/02.mp3
  would remove  playlist my-device-playlist.m3u8 (<player>)
  would copy    Artist - Album/01.flac
```

Pressing Copy on that plan would:

1. **Delete everything in `MUSIC/`**: Music Center transfers, drag-and-drop, an old Sony-sync copy.
   The budget counts it as free space (`free + on_device`), and the sweep runs first, so the plan
   fits.
2. **Put the library at the drive root.** Whether Sony's scanner indexes music outside `MUSIC/` is
   unverified: both of Cinder's SensMe device proofs copied into `/contents/MUSIC`.
3. **Leave `Liked Songs.m3u8` empty after a Flint sync**, because `index_volume` walks only
   `MUSIC/`.

The preview does list every removal, so a careful owner would see it. It is still what the
documentation teaches, and it ends in irreversible deletion.

**Recommended:**
* **Root the sync at `music_dir()`.** If a manifest is found at the drive root, an earlier Flint
  synced there: offer a one-time move, which is a rename on the same volume.
* **Sweep only what the manifest says Flint wrote**, with an explicit opt-in to sweep the rest.
  That is the rule Flint already applies to cover art and lyrics: "sweeping them would delete files
  another tool — or the owner — put on the player".
* At the very least, make Copy confirm the count and size of removals Flint did not write.

## Part E — Open findings

**E2. Copy re-plans.** `Job::Plan` and `Job::Apply` both run `sync_job`, which scans afresh, so a
change to the library or the player between **Show** and **Copy** can produce removals nobody saw.
Keep the shown `Plan`, re-scan cheaply at Copy, and refuse if the copy and removal sets differ.

**E7. The unit that moves together is the top-level folder.** For `Artist/Album/…` libraries (the
layout Flint's own scan test uses) that unit is the artist, so a big discography fits on neither
volume and is skipped whole. Either document "top-level folders", or make the unit the folder that
holds the audio.

**E8. Playlists.**
* Relative entries resolve against the library, not the playlist's folder, which is what M3U
  means.
* A single non-UTF-8 `.m3u` fails the whole sync. Fall back to CP-1252 or lossy decoding, as
  Cinder does.

**E9. Refused scrobbles.** Last.fm's ignored-message code 3 (*timestamp too old*, past 14 days)
can never succeed, but such rows are re-sent on every run. Move them to `.scrobbler.refused.log`
with the reason. Code 4 (*too new*) rows should stay.

**E10. CI.**
* `push: ["**"]` together with `pull_request` runs every PR push twice. Cinder dropped that shape.
* Add `[profile.dev.package.flint-core] opt-level = 3`, or test `flint-core` in release: the
  lossless test takes 25 s in debug.

**E11. Small.**
* `http.rs` still says Last.fm is the only endpoint, but GitHub raw is one too.
* The palette shop opens one WinHTTP session per file, up to 200 TLS handshakes. Reuse the session,
  or publish a bundle from cinder-themes' CI.
* On Unix, `lastfm.conf` is world-readable for a moment before its `chmod`. Create it with
  `OpenOptionsExt::mode`.

**Well done, and worth keeping:**
* No dependencies.
* The FLAC and ID3 writers refuse what they do not understand and write through temp file, `fsync`
  and rename.
* A file whose tag cannot be read is copied untagged rather than failed.
* The shared-palette index cannot produce a path outside the folder.
* Network access is https-only.
* The palette port is faithful: 200,000 random palettes got the same verdict from Cinder's parser
  and Flint's.

## Part G — Features (Flint's share; the full ranked list is in Cinder's audit)

* **G1.1 Back up the player's own state on every connect**: settings, liked list, Cinder's
  playlists and palettes, the scrobble log and art, versioned per player, with a restore.
  `/contents` is the only copy of all of it.
* **G1.2 A player health card.** Cinder writes `cinder_status.txt` when USB-MSC starts (version,
  firmware, last boot, refused files, `/data` free space). Flint shows it, and **Copy a report**
  bundles it with the log tails for a bug report.
* **G1.3 Device-aware transfer.** Flag what the player cannot decode (32-bit FLAC stalls its
  decoder, and Cinder now refuses them) and convert only those: a narrow first slice of the
  planned conversion work.
* **G1.4 Synced lyrics** from LRCLIB (free, no key), as `.lrc` sidecars. Cinder shows them with one
  tap.
* **G1.5 Playlists from listening history** (most played, not played in a year), written into
  `cinder_playlists/`.
* **G1.7 Contract fixtures shared with Cinder**: the palette corpus, likes key vectors, and
  scrobble logs with both `#TZ` headers. F1 and F2 were both drift between two codebases with no
  test across them.
* **G3.1 Library lint**: albums that will split on the player (album artist, year, compilation
  tags) before anything is copied.
* **G3.2 Adopt music already on the player**, by content key, instead of recopying or sweeping it.
  This is F1's migration path.
* **G3.3** Duplicate audio. **G3.4** SensMe tags in M4A, AAC and ALAC: the player parses them;
  the atom needs RE first. **G3.5** A macOS CLI build. **G3.6** Watch for the player and send
  scrobbles when it appears.
